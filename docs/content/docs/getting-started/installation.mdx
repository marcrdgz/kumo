## CLI (recommended)

The `kumo` binary is the daemon + TUI + control CLI in one, installed via the
cargo-dist installer generated by the release pipeline:

```sh
curl --proto '=https' --tlsv1.2 -LsSf https://github.com/marcrdgz/kumo/releases/latest/download/kumo-installer.sh | sh
```

## Desktop app

Installed separately from its `Kumo-<arch>.dmg` on the release page (macOS).
The app manages the whole install: if the `kumo` CLI is missing or outdated it
offers to install/update it, and it can self-update from a newer `.dmg` — all
from inside its interface.

## Nightly

A rolling build of `main` (macOS ARM + Linux x86_64; the full target matrix
can be built on demand via a manual workflow dispatch):

```sh
kumo update --nightly
```

## From source

<Steps>
  <Step>Install a Rust toolchain (`cargo`).</Step>
  <Step>
    Install [Zig](https://ziglang.org) on `PATH` — `build.rs` compiles the
    vendored `libghostty-vt` library at build time (the vendored build pins
    zig `0.15.x`; it rejects `0.16+`).
  </Step>
  <Step>
    ```sh
    cargo install --path app/kumo --locked
    # or: make install
    ```
  </Step>
  <Step>
    Install the agent skill so `opencode`/`claude`/`codex` **automatically** learn checkpoints:

    ```sh
    kumo skills install --global   # writes ~/.config/kumo/kumo-agents.md + mirrors to ~/.config/opencode/AGENTS.md (auto-loaded every session) + skills/kumo/SKILL.md
    ```

    No manual `skill({name:"kumo"})` call needed — `opencode` loads `~/.config/opencode/AGENTS.md` on every session, so checkpoints are applied automatically inside any Kumo pane (`KUMO_SOCKET_PATH` set). Restart agent sessions after install. Verify with `kumo skills get kumo --full` or `cat ~/.config/opencode/AGENTS.md` inside a pane.
    If `opencode` still doesn't update checkpoints, see [Checkpoints → Troubleshooting](/docs/guides/checkpoints#troubleshooting-opencode-not-updating-checkpoints).
  </Step>
</Steps>

<Callout title="macOS with Xcode ≥ 26.5">
  Point builds at the CommandLineTools SDK
  (`DEVELOPER_DIR=/Library/Developer/CommandLineTools`) — the Xcode 26.5 SDK's
  `libSystem.tbd` no longer lists the `arm64-macos` slice, so zig 0.15 fails
  every native link with undefined libSystem symbols. The Makefile exports it
  automatically.
</Callout>

## Updating

The desktop app is the "smart" interface for updates: on launch it checks both
the `kumo` CLI and the desktop app against the latest release, installs the
CLI automatically when it's missing, and shows a one-click banner when either
is outdated.

The TUI keeps its own `kumo update` for the CLI:

```sh
kumo update            # update to the latest stable release
kumo update --nightly  # update to the latest nightly build
kumo update --check    # report availability (exit 0 = up to date, 1 = update)
```

At startup kumo checks (at most once per day for stable, every 6 h for
nightly) for a newer release and, if one exists, shows a banner at the
top-right with a red ✕ to dismiss it. Disable the check with
`update-check = false` in the config or by setting `KUMO_NO_UPDATE=1`.
