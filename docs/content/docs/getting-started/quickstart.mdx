## Launch

```sh
kumo
```

`kumo` attaches to the last session if one exists (else starts fresh) and
starts the daemon behind it if needed. Every new pane opens in the directory
you launched from.

## Meet the leader key

Press <kbd>Ctrl+B</kbd>, then a command key. The status bar shows the
available bindings while you are in leader mode, and <kbd>leader+?</kbd>
opens the full keybind showcase at any time.

## Split panes

- <kbd>leader+v</kbd> — split vertically
- <kbd>leader+-</kbd> — split horizontally
- <kbd>leader+h/j/k/l</kbd> — move focus between panes
- <kbd>leader+z</kbd> — zoom the focused pane

Resize with <kbd>leader+H/J/K/L</kbd>, or just drag a splitter with the mouse.

## Spawn an AI agent

<kbd>leader+a</kbd> opens a dedicated pane running your AI CLI (default
`opencode`, configurable via `ai-cmd`). You can also just run `opencode`,
`claude`, or `codex` inside any shell pane — kumo auto-detects the agent
process and weaves it into the sidebar's **AGENTS** tab with a live status
dot: 🟢 working, 🟠 blocked (waiting for your approval), ⚪ idle. When an
agent blocks or finishes, kumo chimes so you notice without watching.

## Checkpoints — keep humans in the loop

Every worktree carries a lightweight checkpoint: a free-text `comment` + a
`status` (`todo` / `in-progress` / `in-review` / `completed`). Humans read it
in `kumo worktree list --json`; agents keep it fresh **automatically** on every
slice — the TUI does not edit checkpoints, only agents (via `kumo worktree set`) write them.

After `kumo skills install --global`, `opencode` loads `~/.config/opencode/AGENTS.md` on **every** session, so checkpoints are automatic — no `skill({name:"kumo"})` call needed. Just run `opencode` inside a Kumo pane (`leader+a`) and it will:

```sh
kumo worktree current --json
kumo worktree set --comment "reproduced auth failure; testing fix (src/auth.ts)" --status in-progress --json
```

See [Checkpoints](/docs/guides/checkpoints) for the full pattern and
troubleshooting when `opencode` doesn't update.

## Sessions

- <kbd>leader+c</kbd> — create a named session
- <kbd>leader+n</kbd> / <kbd>leader+p</kbd> — cycle sessions
- <kbd>leader+1…9</kbd> — jump to the session at that sidebar position

## Orchestrate agents (and dev servers)

Every `kumo` command is an API an AI inside a pane can use — no SDK:

```sh
kumo agent wait -p 42 --until idle            # server holds the socket, no polling
kumo agent prompt -p 42 "fix the test" --wait idle
kumo agent read -p 42 --source recent         # daemon owns the buffer, alt-screen intact
kumo pane wait-output -p 12 --regex "Ready|passed|failed"
```

See [Orchestration](/docs/guides/orchestration) for the full ADE guide, including the copy-paste skill prompt for agents.

## Detach and come back

<kbd>leader+d</kbd> detaches this terminal; the daemon keeps running in the
background owning your panes and agents. Re-attach from any terminal:

```sh
kumo        # attach to the daemon (starts it if needed)
kumo ls     # list sessions (* = active)
```
