## Launch

```sh
kumo
```

`kumo` attaches to the last session if one exists (else starts fresh) and
starts the daemon behind it if needed. New panes open in the focused pane's
current directory (configurable with `[terminal] new-cwd`).

## Meet the leader key

Press <kbd>Ctrl+B</kbd>, then a command key. The status bar shows a hint while
you are in leader mode, and <kbd>leader+?</kbd> opens a searchable command
palette with every binding.

## Split panes

- <kbd>leader+v</kbd> — split vertically
- <kbd>leader+-</kbd> — split horizontally
- <kbd>leader+h/j/k/l</kbd> — move focus between panes
- <kbd>leader+z</kbd> — zoom the focused pane

Resize with <kbd>leader+H/J/K/L</kbd>, or just drag a splitter with the mouse.

## Spawn an AI agent

<kbd>leader+a</kbd> opens a dedicated pane running your AI CLI (default
`opencode`, configurable via `ai-cmd`). You can also just run `opencode`,
`claude`, or `codex` inside any shell pane — kumo auto-detects the agent
process and lists it in the sidebar with a live status dot: 🔵 working,
🟠 blocked (waiting for your approval), 🟢 done, ⚪ idle. When an agent blocks
or finishes, kumo shows a toast and chimes so you notice without watching;
<kbd>leader+i</kbd> jumps through the agents that need you.

## Install the Kumo skill

Give your agent Kumo's bundled orchestration instructions so it knows how to
discover panes, read terminal output, prompt other agents, and wait without
polling. Install it from **MENU → settings → agents**, or with the one-line
command for your CLI in [Orchestration → Bundled agent
skill](/docs/guides/orchestration#bundled-agent-skill).

## Sessions

- <kbd>leader+c</kbd> — create a named session
- <kbd>leader+]</kbd> / <kbd>leader+[</kbd> — cycle sessions
- <kbd>leader+Alt+1…9</kbd> — jump to the session at that sidebar position

## Tabs

- <kbd>leader+t</kbd> — new tab in the current session
- <kbd>leader+n</kbd> / <kbd>leader+p</kbd> — cycle tabs
- <kbd>leader+1…9</kbd> — jump to the tab at that position

## Give an agent an isolated worktree

Create an ephemeral checkout, start an agent in its new session, and hand it
a task:

```sh
kumo worktree create --ai fix-login --agent claude --note "Investigate auth tests"
kumo agent status                     # find the new agent's pane id, e.g. 42
kumo agent prompt -p 42 "Fix the failing auth tests" --wait idle
```

`--agent` returns once the agent is ready, but it does not submit the task:
send it with `agent prompt`. See [Orchestration](/docs/guides/orchestration#isolated-worktrees-and-checkpoints)
for checkpoints, `--from`, shared directories, and cleanup.

## Orchestrate agents (and dev servers)

Every `kumo` command is an API an AI inside a pane can use — no SDK:

```sh
kumo agent wait -p 42 --until idle            # server holds the socket, no polling
kumo agent prompt -p 42 "fix the test" --wait idle
kumo agent read -p 42 --source recent         # read straight from the daemon's buffer
kumo pane wait-output -p 12 --regex "Ready|passed|failed"
```

See [Orchestration](/docs/guides/orchestration) for the full ADE guide and
command reference.

## Detach and come back

<kbd>leader+d</kbd> detaches this terminal; the daemon keeps running in the
background owning your panes and agents. Re-attach from any terminal:

```sh
kumo        # attach to the daemon (starts it if needed)
kumo ls     # list sessions (* = active)
```
