Kumo auto-detects any AI CLI running inside a pane and lists it in the
sidebar's AGENTS tab with its workspace and CLI name.

## Spawning an agent

<kbd>leader+a</kbd> spawns a dedicated AI pane running your configured CLI
(`ai-cmd`, default `opencode`). Or just run `opencode`, `claude`, `codex`, …
inside any shell pane — kumo detects the process automatically.

## Status at a glance

Each agent shows a status dot, detected from the live terminal buffer (not
just the viewport), so it stays accurate even while you scroll:

- 🟢 **Green** — working
- 🟠 **Orange** — blocked, waiting for your approval
- ⚪ **Gray** — idle

When an agent **blocks** or **finishes**, kumo raises a transient **toast** in
the corner of every attached viewer (click it to jump to the agent's pane)
and plays an audible chime — a distinct sound per event. Blocked agents also
float to the top of the AGENTS list with a filled `◉` dot and a `· blocked`
hint, and their pane glows orange even without focus.

## Agent inbox

<kbd>leader+i</kbd> moves the keyboard into the agent panel. `j`/`k` (or the
arrows) move between the agents that need attention — **blocked · done ·
running** — and <kbd>Enter</kbd> jumps straight to the chosen pane (switching
session and tab as needed). <kbd>Esc</kbd> or <kbd>q</kbd> leaves the inbox.

The sidebar's default layout stacks two panels with bold primary-color
titles: **spaces** on top (sessions + branches), the **agent panel** below,
grouped by state with counts — the grouped tail (idle · unknown) stays
dimmed. Click the panel's right-hand `grouped` descriptor to switch it to
the classic rank-sorted workspace rows (and back). Drag the divider between
the panels to resize them (each side scrolls when the divider leaves less
room than its content). The classic two-tab sidebar remains one config line
away:

```toml
[sidebar]
layout = "divided" # "tabs" | "divided"
```

```toml
[notifications]
position = "top-right"  # top-left | bottom-right | bottom-left | center | off
sound = true            # audible chime on blocked/finished transitions
blocked = true          # toast when an agent blocks
finished = true         # toast when an agent finishes / goes idle
```

## Lifecycle detection

**Process** detection (name + workspace) works for every agent below;
**lifecycle** detection (working / blocked / idle) is per-agent:

### Fully implemented

- `opencode` — permission dialogs, question prompt, prompt-footer signals
- `claude` — approval forms, permission prompts, OSC-title spinner

### Auto-listed, status always idle

- `codex` · `gemini` · `qwen` · `aider` · `cody` · `swe` · `coco`

<Callout title="Agents live in the daemon">
  Lifecycle detection, status, and audible alerts run server-side, so they are
  visible in the sidebar of any attached terminal — and `kumo agent status`
  (`list` / `ls`) surfaces each agent's status and pane id from outside the
  TUI, so a blocked agent is noticeable even when you are not attached.
</Callout>

## Debugging status: `kumo agent explain`

Detection is heuristic, so kumo can explain on demand why any pane reads the
status it does — evaluated **live by the running daemon** against the pane's
terminal buffer:

```sh
kumo agent status            # who runs, and where (e.g. pane 42 · work:t1:p2)
kumo pane list               # every pane id + s/t/p position (optional -t filter)
kumo agent explain 42        # or by position: s1:t2:p1, work:t2:p1 (with -s: t2:p1)
```

Both the id and the composite position (`[s:]t[:p]`, 1-based) are accepted —
positions are friendly for interactive use, ids stay stable for scripts.

The `cpu`/`mem` line covers the agent's **whole process tree** (children
included) with CPU measured over a sliding ~6 s window, so a bursty agent
reads a truthful average instead of flat 0%.

The report shows the matched **markers** for each agent (opencode / claude)
with the **evidence region** they were found in — `screen` (buffer tail),
`form` (below the last rule — Claude's live prompt), `footer` (opencode's
prompt footer), or `title` (OSC window title) — the **precedence** that
decided the winner (blocked > working > idle > unknown), and the **reason
chain** behind an idle verdict: explicit idle markers, unseen-finish hold
(`done` until focused), seen-after-focus, dead pane, the not-an-AI-CLI
default, or the no-signal fallback (`unknown`). Raw vs. displayed status
differ when the done/seen rule is active, which the report makes explicit.
