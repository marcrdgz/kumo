<kbd>leader+d</kbd> (or MENU → `detach`) detaches **this terminal**; the
daemon keeps running in the background, owning your panes, their processes,
and their agents. Re-attach from any terminal with `kumo` or `kumo attach`,
and everything is exactly where you left it.

## How it works

- The daemon owns the PTYs and the terminal emulators; attached terminals are
  light renderers that draw cell patches and forward input.
- Rendering streams **dirty-row cell patches**, so re-attach is exact and
  several terminals can watch the same session at once.
- The daemon **auto-stops** when the last session closes — no lingering
  background process.
- Sessions **survive a reboot** (see below).
- `kumo new` always starts a fresh session; it never attaches to an existing
  one.

## Security

The IPC socket lives in `$XDG_RUNTIME_DIR/kumo` with owner-only permissions
(`0o600`), and every accepted connection is checked to belong to the same
user (`SO_PEERCRED` on Linux, `getpeereid()` on macOS/BSD) — a different
user's client is rejected, fail closed.

## Updating without losing the web

`kumo update` swaps the binary and the daemon restarts **in place**
(`daemon --resume`), inheriting the live terminals from a transient resume
file — running agents survive the update, attached terminals auto-reconnect
over the fresh socket, and each pane restores its screen and scrollback.

## Surviving a reboot

The daemon keeps `~/.local/state/kumo/state.json` current: layout changes are
saved within seconds, screen contents at most every
`[persistence] autosave-interval` (2 minutes by default), and a final save
runs when the OS stops the daemon at shutdown or logout. Only panes with new
output are re-encoded, and the write happens off the daemon's render loop.

After a reboot (or a crash), the first `kumo` starts the daemon cold and it
restores every session, tab and split:

- each shell reopens in the directory it was in, showing its saved screen and
  scrollback above a dim `-- restored by kumo --` line;
- agent panes relaunch their last conversation (`claude --continue`,
  `codex resume --last`, `opencode --continue`,
  `aider --restore-chat-history`), typed into the restored shell so a failed
  resume leaves you at a prompt. Disable with `resume-agents = false`;
  add or change an agent's command with `resume = [...]` in its
  [detection manifest](/docs/guides/agents);
- names and agent aliases come back, so scripts keep working.

Running processes other than agents (servers, editors, builds) are not
relaunched. `kumo kill` and closing the last session end the sessions for
good: nothing is restored afterwards. Turn the whole feature off with
`[persistence] restore = false`.
