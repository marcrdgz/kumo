Kumo has three levels: a **session** is a workspace (usually one repository or
worktree), a session holds one or more **tabs**, and each tab is a **binary
split tree** of panes — every split divides a pane into two, vertically or
horizontally.

All operations live behind the leader key (<kbd>Ctrl+B</kbd> by default). The
full table, with action ids for remapping, is in
[Keybindings](/docs/guides/keybindings).

## Panes

| Keys | Action |
| --- | --- |
| <kbd>leader+v</kbd> / <kbd>leader+-</kbd> | Split the focused pane vertically / horizontally |
| <kbd>leader+h/j/k/l</kbd> | Move focus left/down/up/right |
| <kbd>leader+Tab</kbd> | Cycle focus between panes |
| <kbd>leader+H/J/K/L</kbd> | Resize the focused pane |
| <kbd>leader+z</kbd> | Zoom the focused pane |
| <kbd>leader+s</kbd> | Swap the focused pane with its sibling |
| <kbd>leader+o</kbd> | Rotate the pane layout |
| <kbd>leader+q</kbd> | Show pane numbers — press a number to jump |
| <kbd>leader+x</kbd> | Close the focused pane |

Closing a pane that runs an agent or a full-screen program asks for
confirmation first (<kbd>y</kbd>/<kbd>Enter</kbd> to close, <kbd>n</kbd> or
<kbd>Esc</kbd> to keep it).

## Tabs

Tabs (windows) let one session hold several pane trees. The tab bar at the top
shows each tab's position and name; an unnamed tab is named after its focused
pane (the agent, the running command, or the directory), and renaming it to an
empty name restores that.

| Keys | Action |
| --- | --- |
| <kbd>leader+t</kbd> | New tab |
| <kbd>leader+n</kbd> / <kbd>leader+p</kbd> | Next / previous tab |
| <kbd>leader+1…9</kbd> | Jump to the tab at that position |
| <kbd>leader+,</kbd> | Rename the active tab |
| <kbd>leader+&</kbd> | Close the active tab |

The tab bar is also clickable: `+` opens a tab, the hover-revealed `✕` closes
one, and right-click opens a context menu. From scripts use `kumo tab list`,
`new`, `focus`, `rename` and `kill`, where `TAB` is the tab id, `t2` for the
second tab, or its name (see the [CLI reference](/docs/cli#sessions--tabs)).

## Sessions

| Keys | Action |
| --- | --- |
| <kbd>leader+c</kbd> | Create a new session (name it in the popup) |
| <kbd>leader+w</kbd> | Create a git worktree in a new session |
| <kbd>leader+]</kbd> / <kbd>leader+[</kbd> | Next / previous session |
| <kbd>leader+Alt+1…9</kbd> | Jump to the session at that sidebar position |
| <kbd>leader+b</kbd> | Toggle the sidebar |

Closing a session with busy panes (agents or running programs) lists what is
running and asks for confirmation. `rename-session`, `close-session` and the
`workspace-finder` (search across sessions and tabs) have no stock key: run
them from the <kbd>leader+?</kbd> palette or bind them.

## Sidebar

The default **project** layout lists every session/worktree flat: the session
name with its AI status dot, its branch dimmed underneath, and every agent
inline. The active worktree is expanded; inactive ones collapse to one line.
<kbd>leader+f</kbd> (or `⌕ find` at the top) filters the list. Drag the
sidebar's right edge to resize it (20–50 columns).

The classic SESSIONS/AGENTS panels remain available with `[sidebar] layout =
"divided"` (stacked) or `"tabs"` (two toggled tabs) — see
[Configuration](/docs/configuration#sidebar).

## Mouse

Mouse gestures are positional hit-testing, not key sequences, so they are not
remappable:

- **Drag** selects text (copied on release) — works even in apps with mouse
  reporting. For keyboard selection see [Copy-mode](/docs/guides/copy-mode).
- **Click** is forwarded to the app when it owns the mouse.
- **Scroll** is forwarded to reporting apps; otherwise it scrolls the pane's
  scrollback.
- **Drag a splitter** to resize.
- The **MENU** button (right of the mode chip in the status bar) opens
  `config` (edit `config.toml` in a pane), `settings` (theme and agent
  skills), `reload`, `keybinds` (the <kbd>leader+?</kbd> palette) and
  `detach`.
