**Kumo** (蜘蛛 — *spider* in Japanese) is a terminal multiplexer that weaves
your AI agents together into a single **web** 🕸️. Every pane is a live
terminal, every AI CLI you run (`opencode`, `claude`, `codex`, …) is a thread
in that web, and the sidebar keeps you aware of what each agent is doing at a
glance — because a spider always knows what's happening in its web.

It is built in **Rust** with a single TUI frontend on **ratatui**, real
terminal emulation from **libghostty-vt** (Ghostty's headless terminal core),
and **portable-pty** for PTY management.

And it's featherweight 🪶: while you work, kumo itself idles at **~0.7% CPU
and ~6 MB of memory** — the real cost is whatever you run *inside* its panes,
not the multiplexer.

## Features

- 🖥️ **Real terminal emulation** — each pane is a genuine VT/xterm emulator
  (vendored Ghostty). Shells, TUIs, and full-screen apps behave exactly like
  in a native terminal: cursor, colors, scrollback, the works.
- 🧩 **Split panes & sessions** — binary split tree (vertical/horizontal),
  mouse-drag resizing, zoom, multiple independent sessions, tab cycling.
- 🤖 **AI CLI panes** — spawn a dedicated pane running your AI CLI with one
  keystroke, or run any agent in a shell pane: kumo auto-detects the process
  and weaves it into the sidebar.
- 🟢🟠⚪ **Agent status at a glance** — each agent shows a status dot:
  green = working, orange = blocked (waiting for approval), gray = idle.
  Detected from the live terminal buffer, so it stays accurate while you
  scroll.
- 🔔 **Audible alerts** — a distinct chime when an agent blocks or finishes;
  blocked agents float to the top of the AGENTS list and their pane glows
  orange, even without focus.
- 📋 **Native text selection** — drag to select in any pane, even inside apps
  that own the mouse (opencode's TUI, vim, less).
- 🐣 **Plain-tty identity** — panes present as a plain `xterm-256color` (no
  mouse capabilities advertised), so apps don't hijack the mouse and
  selection always works.
- 🕸️ **Orchestration** — `kumo agent wait/prompt/read` and `kumo pane wait-output` let agents (and you) drive any pane and wait without polling — pinned to the pane occupant, bracketed-paste aware. See [Orchestration](/docs/guides/orchestration).
- 📂 **Workspace-aware** — kumo opens in the directory you launch it from;
  every new pane/session starts there.
