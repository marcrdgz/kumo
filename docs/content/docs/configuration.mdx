Kumo reads a single config file at `~/.config/kumo/config.toml`. The old flat
`key = value` file at `~/.config/kumo/config` (and the legacy `~/.kumo`)
still reads as a fallback, but `config.toml` wins when both exist.

```toml
# ~/.config/kumo/config.toml

ai-cmd = "claude --model sonnet"
update-check = true

theme = "tokyo-night"

[terminal]
shell = "/bin/zsh"
new-cwd = "follow"      # follow | current | home | fixed

[keymap]
leader = "ctrl+b"

# Leader bindings are remappable: override a stock key or add a new one.
[keymap.bindings]
s = "split-vertical"   # now leader+s splits vertically
x = "close-pane"

[notifications]
position = "top-right"  # top-left | bottom-right | bottom-left | center | off
sound = true            # audible chime on blocked/finished transitions

[worktree]
shared-dirs = ["node_modules", ".cache"] # gitignored dirs shared by worktrees
expose-socket = true    # pass KUMO_SOCKET_PATH and KUMO_BIN_PATH to panes

[persistence]
restore = true          # bring sessions back after a reboot, logout or crash
autosave-interval = 120 # max age (seconds) of saved screen contents; 0 = on shutdown only
resume-agents = true    # relaunch agents with their resume command (claude --continue, …)
```

## Config builder

The generator writes only what differs from the defaults, in canonical form.
Paste the result into `~/.config/kumo/config.toml`; the daemon reloads it
automatically. `kumo reload` remains available for an explicit refresh.

## Agent skill

`ai-cmd` chooses which AI CLI Kumo starts. Installing Kumo's bundled skill in
that agent is a separate, one-time step — see
[Orchestration → Bundled agent skill](/docs/guides/orchestration#bundled-agent-skill).

## Terminal

| Key | Description |
| --- | --- |
| `shell` | Login shell used to spawn panes. Defaults to `$SHELL`, then `/bin/zsh`. |
| `new-cwd` | Where new panes and sessions start: `follow` (default) follows the focused pane's working directory live; `current` freezes the directory kumo was launched from; `home` uses `$HOME`; `fixed` uses `fixed-cwd`. |
| `fixed-cwd` | Directory used when `new-cwd = "fixed"`. |

## Theme

Pick a built-in theme with `theme = "<name>"` (or `[theme] name = "<name>"`).
Names are case-insensitive and prefix-matched, so `gruvbox` selects
*Gruvbox Dark*. The theme picker (MENU → `settings`) writes the same key. See
[Themes](/docs/guides/themes) for the list and for `[theme.custom]`.

## Sidebar

```toml
[sidebar]
layout = "project"        # project | divided | tabs
width = 28                # project layout only; 20..50, also draggable
order = ["sessions", "agents"]  # divided/tabs: section order

[sidebar.sections]
sessions = true
agents = true

[sidebar.borders]
style = "rounded"         # single | rounded | double | heavy | hidden
```

`project` (aliases `explorer`, `navigator`) lists worktrees with inline
agents; `divided` (alias `stacked`) stacks the SESSIONS and AGENTS panels;
`tabs` toggles between them. `[sidebar.borders] style` also styles pane
borders. At least one section always stays visible.

## Status bar

```toml
[status_bar]
enabled = true
left   = ["mode", "menu", "session"]
center = ["branch", "github"]
right  = ["agent_status", "clock"]

[status_bar.widgets.clock]
format = "%H:%M"

[status_bar.widgets.branch]
show_ahead_behind = true
max_len = 20

[status_bar.widgets.agent]
style = "counts"          # counts | dots | list
only_blocked = false

[status_bar.widgets.hostname]
style = "short"           # short | fqdn
show_user = false
only_ssh = false

[status_bar.widgets.session]
show_tabs = true
show_panes = true
show_zoom = true
```

The values above are the defaults. Available widgets: `mode`, `menu`,
`session`, `branch`, `github` (the current branch's pull request, via `gh`),
`agent_status`, `hostname`, `clock`. `[status-bar]` is accepted as an alias of
`[status_bar]`.

## Worktree isolation

The optional `[worktree]` section controls what new isolated worktrees share
with the primary checkout:

| Key | Description |
| --- | --- |
| `shared-dirs` | Relative, gitignored directories to link into each new worktree (for example `node_modules` or `.cache`). Absolute paths and paths containing `..` are ignored. Missing, non-directory, or non-gitignored sources are skipped with a warning. |
| `expose-socket` | When `true` (the default), panes receive `KUMO_SOCKET_PATH` and `KUMO_BIN_PATH` so an agent can drive its own Kumo session. |

For files that should be copied rather than shared, add a `.worktreeinclude`
file at the repository root. It uses the same pattern syntax as `.gitignore`,
including `*`, `**`, `?`, character ranges, comments, root-anchored patterns,
and `!` negations. Matching files must also be ignored by Git. For example:

```text
# Local configuration copied into each isolated checkout
/.env
app/**/.env
!app/fixtures/**
.vscode/settings.json
```

These paths are copied when `kumo worktree create --ai` creates a checkout.

`--agent` starts the agent and replies once it is ready, but does not send a
task: submit work with `kumo agent prompt` (see
[Orchestration](/docs/guides/orchestration#isolated-worktrees-and-checkpoints)).

## File locations

Overrides follow the usual conventions:

| Location | Path / override |
| --- | --- |
| Config | `~/.config/kumo/config.toml` — override with `KUMO_CONFIG_DIR` or `XDG_CONFIG_HOME` |
| Runtime state | `~/.local/state/kumo/` (including the saved sessions, `state.json`) — override with `KUMO_STATE_DIR` or `XDG_STATE_HOME` |
| IPC socket | `$XDG_RUNTIME_DIR/kumo`, else `$TMPDIR/kumo` (the usual case on macOS), else `/tmp/kumo` |
| Agent detection rules | `<config dir>/agent-detection/<agent>.toml` |

## Environment variables

| Variable | Effect |
| --- | --- |
| `KUMO_CONFIG_DIR` | Config directory (default `~/.config/kumo`, or `$XDG_CONFIG_HOME/kumo`) |
| `KUMO_STATE_DIR` | State directory (default `~/.local/state/kumo`, or `$XDG_STATE_HOME/kumo`) |
| `KUMO_NO_UPDATE=1` | Disable the startup update check |
| `KUMO_NO_NOTIFY=1` | Disable agent toasts |
| `KUMO_NO_SOUND=1` | Disable the agent chime |
| `KUMO_BIN_PATH` | Set **inside panes**: the `kumo` binary that owns the pane |
| `KUMO_SOCKET_PATH` | Set **inside panes**: the daemon's socket |

`KUMO_BIN_PATH` and `KUMO_SOCKET_PATH` are only exported when
`[worktree] expose-socket = true` (the default).

## Live reload

The daemon watches the canonical, flat, and legacy config files plus
`agent-detection/*.toml`, then applies the same reload path automatically.
`kumo reload` (or MENU → `reload`) triggers it explicitly. `shell` and
`ai-cmd` apply to panes spawned from then on; `keymap.bindings`, `new-cwd`, the
theme, the status bar, the sidebar width and `[notifications]` apply
instantly. The leader key is read when a client starts: detach and re-attach
to pick up a new `[keymap] leader`. MENU → `config` opens the config
file in an editor pane inside the session (`$VISUAL` → `$EDITOR` → `vi`).
