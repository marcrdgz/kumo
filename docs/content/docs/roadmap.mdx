The long-term goal is that **every aspect of kumo is configurable by you**:
colors, keybindings, the leader key, the layout of the status bar and
sidebar, the AI panes, and more. Every `0.x.0` is a feature release; 1.0.0 is
the finish line for the configurable, persistent kumo.

<Callout type="info" title="Current: v0.7 ADE — next: 0.8.0, the 1.0 release candidate">
  0.7 provides server-owned agent waits, prompts, reads, output waits,
  startup, aliases, broadcast, and isolated worktrees with lightweight

## Next up

- **0.7.0 — ADE & AI polish**: ✅ **agent orchestration primitives** (`kumo agent wait --until`, `agent prompt --wait`, `agent read --source`, `pane wait-output --regex`, `agent start/rename/broadcast` — server-owned, occupant-pinned, bracketed-paste-aware; see [Orchestration](/docs/guides/orchestration)) — the *wait* half of `send-keys`. Lifecycle detection for `codex`, `gemini`, `qwen`, `aider`, `cody`, `swe`, `coco`; **agent inbox view** — `leader+i` keyboard-routes to `blocked · done · running` agents, the sidebar defaults to stacked spaces + agent panels (grouped sections, draggable grey divider at the middle, `[sidebar] layout = "tabs"` restores the classic two-tab sidebar); **`kumo agent explain`** — live, daemon-side diagnostics of why a pane reads the state it does (matched markers, evidence region, verdict reason chain) with `kumo agent status`/`list` and `kumo pane list` for pane-id discovery; **isolated worktrees and lightweight checkpoints** — `worktree create --ai` supports `--from`, `--note`, and `--agent`, with `list/current/set/open/rm` for inspection and cleanup; config file-watcher hot-reload (deferred from 0.6.0). The current flow requires an explicit `kumo agent prompt` after an agent is ready; automatic task submission is planned for 0.7.1. A dedicated TUI broadcast popup and `leader+B` binding are not part of 0.7.0.
- **0.8.0 — Contracts, persistence & freeze (RC)**: no new surface beyond
  reboot recovery. Stable wire protocol, a frozen `--json` machine API (golden
  tests, error codes, exit codes), deterministic keymap conflicts, a
  readiness-gated `worktree create --agent`, an upgrade path tested against
  the 0.7.6 release, sessions that survive a reboot (cwd, screens and agents
  via `claude --continue` & co.), and a written
  [compatibility policy](/docs/compatibility).
- **1.0.0 — Full customization + solid persistence**: the 0.8.0 build with
  the version bumped — frozen TOML schema v1, stable keymap and theme system,
  crash-safe persistence, proven release pipeline.
- **2.0.0 — Plugins**: plugins are a new public API surface, so they land
  after 1.0 freezes what kumo already ships.

## After 1.0

1.x releases are additive within the compatibility policy: Windows parity,
`kumo doctor` diagnostics, CI-tracked benchmarks, fuzzing, semantic session timeline (time-travel scrollback), kumo as
an MCP server so any agent can drive it, a multi-agent supervisor, session
migration across machines, declarative workspaces, and tmate-style session
sharing.
