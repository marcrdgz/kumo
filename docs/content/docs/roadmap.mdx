The long-term goal is that **every aspect of kumo is configurable by you**:
colors, keybindings, the leader key, the layout of the status bar and
sidebar, the AI panes, and more. Every `0.x.0` is a feature release; 1.0.0 is
the finish line for the configurable, persistent kumo.

<Callout type="info" title="Current stable: v0.6.x">
  See [CHANGELOG](https://github.com/marcrdgz/kumo/blob/main/CHANGELOG.md) for
  the full release history, and
  [ROADMAP.md](https://github.com/marcrdgz/kumo/blob/main/ROADMAP.md) for the
  detailed plan.
</Callout>

## Next up

- **0.7.0 — Agent breadth & AI polish**: lifecycle detection for `codex`,
  `gemini`, `qwen`, `aider`, `cody`, `swe`, `coco`; **agent inbox view** —
  `leader+i` keyboard-routes to `blocked · done · running` agents, the sidebar
  defaults to stacked spaces + agent panels (grouped sections, draggable grey
  divider at the middle, `[sidebar] layout = "tabs"` restores the classic
  two-tab sidebar); **`kumo agent explain`** — live, daemon-side diagnostics of
  why a pane reads the state it does (matched markers, evidence region, verdict
  reason chain) with `kumo agent status`/`list` and `kumo pane list` for
  pane-id discovery; OSC 133 command-traceback context sharing; broadcast
  prompt to agents (`leader+B`, fan one prompt to every AI pane — replaces
  tmux sync-input); config file-watcher hot-reload (deferred from 0.6.0).
- **0.8.0 — Stability**: signal hardening, stable CI, complete config docs +
  `kumo doctor` diagnostics (duplicate keymaps, invalid TOML), state-migration
  and `kill -9` crash-safety harness, published benchmarks with concrete targets
  (attach latency, memory/pane, keystroke→render); Windows experimental.
- **0.9.0 — QoL & plugins (RC)**:`kumo-plugin.toml` plugins — unified `[[entry]]` manifest (`command`/`trigger`/`boot`/`pane` kinds + `link` interception), `api` generation gate, users bind plugin entries in their own `[keymap.bindings]`, release-tarball-first install with pinned lockfile + semver-aware `upgrade`, host-managed state dir, `KUMO_BIN_PATH` + full CLI as API, `kumo plugin add owner/repo` + `kumo-plugin` topic marketplace (index parses manifests) — plus command palette, system notifications, tmux control-mode compat, asciinema export, and optional `[terminal] scrollback-limit` — QoL only, not a 1.0 gate.
- **1.0.0 — Full customization + solid persistence**: frozen TOML schema v1
  (every state bump ships a migration test), stable keymap and theme system,
  crash-safe persistence, proven release pipeline (0.9.0 is the RC).

## After 1.0

With the plugin system shipped in 0.9.0, After 1.0 extends it — plus
Windows parity, semantic session timeline (time-travel scrollback), kumo as
an MCP server so any agent can drive it, a multi-agent supervisor, session
migration across machines, declarative workspaces, and tmate-style session
sharing.
